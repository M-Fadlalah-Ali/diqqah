## 0. قاعدة الالتزام بالقاموس (جوهرية)

1. **المصطلح الواحد لكل مفهوم**: ما دوّن في هذا القاموس هو التسمية المعتمدة حصراً في الواجهة العربية والتقارير ووثائق المشروع. أي مرادف (ولو شائعاً في السوق) يُرفض في مراجعة الكود والواجهة.
2. **الكود يتبع الإنجليزية في وثيقة 05**: أسماء الجداول والحقول في الكود تبقى بالإنجليزية كما في 05 (مثل `invoice`, `party`, `qty_base`)، والمصطلح العربي هنا هو ما يُعرض للمستخدم ويُكتب بالتقارير.
3. **إضافة مصطلح جديد** تمر عبر تحديث هذا الملف بإصدار جديد — لا يُستخدم مصطلح في وثيقة أو كود قبل توثيقه هنا.
4. تعريف كل مصطلح هنا **استخدامي** (ما يعنيه داخل «دِقَّة» تحديداً) لا قاموسي عام.
5. **القاموس لا يُقفل**: يبقى مفتوحاً لما يستجد من مصطلحات ممارسة المالك اليومية حتى المراجعة النهائية وما بعدها (م-09/D-038).

## 1. عام والتطبيق

| المصطلح المعتمد | الإنجليزية | المعنى الدقيق في «دِقَّة» |
|---|---|---|
| دِقَّة (Diqqah) | Diqqah | اسم التطبيق (D-020 كما عدّله D-025): الرسم بالتشكيل في الشعار والمواد، و«دقة» في النص الجرد؛ لاتينياً Diqqah في النصوص والمواد والواجهة وdiqqah في المعرفات التقنية |
| القاعدة | Database | قاعدة SQLite الواحدة على الجهاز، تضم كل الشركات والمستخدمين (05) |
| الجهاز الرئيسي | Primary device | جهاز المحل المشترك (حاسوب غالباً) الذي يعمل عليه الفريق بحسابات منفصلة حتى مرحلة المزامنة (09 §7) |
| جسر التصدير/الاستيراد | Transfer bridge | نقل بيانات يدوي بملف مغلق بين جهازين قبل المزامنة — حل مؤقت معتمد (09 §7) |
| الشركة | Company | كيان محاسبي مستقل تماماً بدليله وفواتيره وصناديقه (D-015). لا دمج بين الشركات أبداً |
| الشركة الافتراضية | Default company | الشركة الوحيدة التي تُنشأ تلقائياً وتعمل بها كل مراحل ما قبل المرحلة 2 |
| النسخة الاحتياطية | Backup | ملف واحد كامل للقاعدة، **مشفّر إلزامياً من م1 بمفتاح البرنامج حصراً بلا كلمة مرور** مع خيار الإلغاء الواعي (م-47/D-050، عُدّلت الآلية D-060 — حسم س12)، يُستعاد كاملاً أو لا شيء (F-012) |
| نسخة ما قبل الاستعادة | Pre-restore snapshot | نسخة طارئة آلية تُلتقط قبل كل استعادة وتُسمّى بتاريخها — وهي طريق الرجوع الوحيد، لا زر رجوع مستقل (س4) |
| وضع التصفح | Read-only mode | فتح قاعدة أحدث مخططاً على تطبيق أقدم للقراءة فقط (تصفح/طباعة/تصدير) بشارة «قاعدة من إصدار أحدث — تصفح فقط» ومنع كل كتابة (س4) |
| المرحلة | Phase | إحدى مراحل 0–5 في وثيقة 09؛ مرحلة واحدة نشطة فقط في كل وقت |

|---|---|---|

| كشف الحساب | Statement | تقرير حركة طرف معين زمنياً برصيد جارٍ |

## 3. الأصناف ووحدات القياس

| المصطلح المعتمد | الإنجليزية | المعنى الدقيق في «دِقَّة» |
|---|---|---|
| الصنف | Item | وحدة البيع/الشراء في الدليل: بضاعة أو خدمة أو تجميعي (`kind`) |
| البضاعة | Good | صنف تخزيني يتتبع بالكمية والتكلفة في المستودع |
| الخدمة | Service | صنف بلا مخزون؛ قيدها إيراد مباشر بلا حركة مخزون |
| الصنف التجميعي | Bundle | صنف يُباع كوحدة لكنه يسحب مكوناته من المخزون عند الترحيل وفق وصفته |
| الوصفة (المكونات) | Recipe / components | قائمة مكونات الصنف التجميعي وكميات كل مكون (`bundle_component`) |
| وحدة القياس | Unit | وحدة الكم: قطعة، كيلو، علبة... لكل صنف وحدة أساسية واحدة |
| الوحدة الأساسية | Base unit | وحدة تخزين وترصيد الصنف؛ عاملها 1 دائماً وكل الكميات تُخزن بها أعداداً صحيحة حصراً — تُختار أدق تجزئة (غرام لا كيلو) فالكسر إدخال/عرض تترجمه الشاشة آلياً (1.5 كغ ← 1,500 غ) (س7) |
| وحدة التعبئة | Packing unit | وحدة أعلى من الأساسية (علبة = 12 قطعة) بعامل تحويل ثابت نحو الأساسية |
| عامل التحويل | Conversion factor | عدد صحيح لا عائم: عدد الوحدات الأساسية في وحدة التعبئة. لا يُعدل بعد وجود حركات على الوحدة — تُنشأ وحدة جديدة بدلاً منه (05 §3.2، س7) |
| لقطة الوحدة | Unit snapshot | تخزين الوحدة وعاملها وقت العملية في سطر المستند (`unit_id`, `factor_at_entry`) حتى لا يشوّه تغيير العامل لاحقاً التاريخ |
| الرمز (SKU) | SKU | رمز الصنف الفريد في الدليل |
| التصنيف | Category | نص اختياري يجمع أصناف متشابهة (`category`) — أساس الرفع الجماعي للأسعار؛ لا يلمس التقييم ولا القيود (F-165) |

## 4. المستودعات والمخزون

| المصطلح المعتمد | الإنجليزية | المعنى الدقيق في «دِقَّة» |
|---|---|---|
| المستودع | Warehouse | مكان تخزين له ترصيد مستقل. واحد في المرحلة 1 والبنية تعددية منذ البداية |
| حركة المخزون | Stock move | أي تغيير كمية صنف في مستودع بمصدر مستند دائماً (فاتورة، مردود، تحويل، تسوية جرد) |
| التحويل | Stock transfer | مستند نقل كمية بين مستودعين يولّد حركتين متقابلتين (خروج/دخول) بلا قيد مالي (إلا فروق ترحيل لاحقاً) |
| الجرد | Stock count | عدّ فعلي لكميات مستودع ومقارنتها بالنظام بفروقاتها |
| تسوية الجرد | Count adjustment | مستند معالجة فروق الجرد: يولّد حركة تسوية وقيد فروق (عجز → مصروف، زيادة → إيراد آخر) |
| الرصيد | Balance | كمية الصنف في المستودع — مشتقة من الحركات وتُخزن في جدول مجمّع قابل لإعادة البناء والفحص (`stock_balance`) |
| التقييم | Valuation | بالمتوسط المرجح المتحرك — آلية التكلفة الواحدة المعتمدة حالياً (م-12/D-039)؛ وإتاحة أكثر من آلية جرد ضمن خيارات المدير بند مستقبلي في قائمة انتظار 09 |
| لقطة التكلفة | Cost snapshot | كلفة الوحدة الأساسية تُكتب في كل حركة وحدث وقت وقوعها؛ إعادة البناء تعيد القيم نفسها ولا تعيد الحساب من الصفر (س1) |
| قاعدة التقريب | Rounding rule | المتوسط المرجح عند القسمة يُقرَّب لأقرب وحدة صغرى والنصف بعيداً عن الصفر؛ وآخر خروج يمتص فارق التوزيع: 100,000 ÷ 3 ← 33,333 + 33,333 + 33,334 (س7) |
| منع السالب | Non-negative rule | لا حركة تجعل رصيد صنف في مستودعه أو رصيد صندوق تحت الصفر؛ صلاحية السماح بالسالب بيد **المدير وقابلة للتفويض** لغيره (م-46/D-049)، ويبقى علاج السالب حصراً بوثيقة إدخال/إخراج أو تسوية (س8) |
| المستودع الافتراضي | Default warehouse | مستودع يختاره المستخدم في إعداداته ويُعرض مبدئياً عند مستندات كالمردود — والاختيار النهائي بيد المستخدم (س8) |
| تسوية التحويل | Mechanism-change settlement | عند تغيير آلية معالجة البيانات: رسالة أثر + نافذة تعرض الدفتري والقيمة بالآلية الجديدة والفرق + قيد تسوية واحد؛ والمستندات المرحّلة لا تُفتح ولا تُعدل (س1) |
| التكلفة | Cost | كلفة الوحدة الأساسية بالعملة الأساسية وقت الدخول (`unit_cost_base_minor`) |

## 5. المستندات وحالاتها

| المصطلح المعتمد | الإنجليزية | المعنى الدقيق في «دِقَّة» |
|---|---|---|
| المستند التشغيلي | Operating document | فاتورة، سند، تحويل مستودع، تسوية جرد — كل ما يولّد حركات عند تأكيده |
| المسودة | Draft | مستند لم يُرحّل بعد؛ قابلة للتعديل والحذف بحرية، بلا أثر محاسبي |
| الترحيل | Posting | تمرير المستند عبر محرك الترحيل: توليد القيد المتوازن والحركات والترقيم النهائي — نقطة اللاعودة |
| مرحّل | Posted | مستند عبر الترحيل؛ لا يُعدل ولا يُحذف أبداً (07 §1.3) |
| العكس / المنعكس | Reversal | تصحيح مرحّل بمستند معاكس يحمل مرجع الأصل (مردود أو قيد عكسي). كلمة «حذف» ممنوعة عن المرحّل |
| آلة الحالات | State machine | حالات المستند المعلنة وانتقالاتها المحروسة بدالة تحقق واحدة (07 §1.2) |
| الترقيم التسلسلي | Numbering | تسلسل سنوي بلا فجوات لكل نوع مستند لكل شركة — والصيغة الجديدة D-169 (س56): سنة برقمين فالعدّاد مبطناً بعرض يحدده المالك (3–8، افتراضه 6) بلا فاصل: «فاتورة بيع 26000001»؛ والصادرة قبل D-169 بصيغة «2026/000001» بيانات لا تُمسّ؛ الأرقام المُصدَر لا تعود للدورة (07 §1.9) |
| تقرير الترقيم | Numbering report | يثبت تسلسل كل (نوع، سنة): كل رقم له مستند أو مستند معاكس — صفر فجوات، دليل للمحاسب والمفتش (س4) |
| لقطة السعر/الصرف | Snapshot | تخزين القيم وقت العملية (سعر صرف، مكافئ بالأساس) بدل حسابها عند العرض (07 §1.7) |

## 6. الفواتير والمردودات

| المصطلح المعتمد | الإنجليزية | المعنى الدقيق في «دِقَّة» |
|---|---|---|
| الفاتورة | Invoice | مستند بيع أو شراء (`invoice`)؛ هي نقطة بدء العملية في MVP — لا أوامر ولا أوراق شحن (07 §3.2) |
| فاتورة البيع | Sale invoice | بيع للعميل: نقدية (تتطلب صندوقاً) أو آجلة (تتطلب طرفاً وتولّد ذمة) |
| فاتورة الشراء | Purchase invoice | شراء من المورد، نقدي أو آجل |
| المردود | Return | مستند إرجاع كلي أو جزئي بمرجع الفاتورة الأصلية: مردود بيع ومردود شراء (`original_invoice_id`) |
| بنود الفاتورة | Invoice lines | سطور الصنف: كمية، وحدة، لقطة العامل، سعر، خصم سطر، إجمالي بالوحدة الصغرى |
| الخصم | Discount | تخفيض على مستوى السطر يُعرض صافياً في الإجمالي — لا حساب محاسبي منفصل للخصم في MVP |
| خصم الفاتورة | Invoice discount | حقل نسبة على المسودة يُترجم مبلغاً ويظهر سطراً في الطباعة ويُقيَّد صافياً بلا حساب مستقل — لا يمس كلفة المخزون، لا سالب ولا تجاوز للإجمالي، وتصحيحه مردود (س7) |
| المدفوعة/الجزئية | Paid / partially paid | حالتان مشتقتان آلياً من (الإجمالي − المطابقات − المردودات المرتبطة) — لا ضبط يدوي أبداً (س5) |

|---|---|---|

| سند القبض | Receipt voucher | استلام مبلغ (من عميل غالباً) في صندوق، مع مطابقة الفواتير المغطاة |

| نافذة المصروف والمدفوعات | Quick expense dialog | نافذة حوارية مبسطة لتسجيل المصروفات والمدفوعات بلا طرف: المبلغ وباب المصروف والسبب؛ القيد يولَّد آلياً في الخلفية ولا يُرى في وجه المستخدم — للمحاسب والمراجع في الدفتر والتقارير (س8) |
| حركة الصندوق | Cash movement | كل تغيير في صندوق له مستند مصدر (سند، فاتورة نقدية، تحويل) — لا حركة بلا مصدر (05 §4.2) |

| تسوية الصندوق | Cash reconciliation | مطابقة الرصيد الفعلي مع الرصيد الدفتري وتسجيل الفرق بقيد |
| المسحوبات الشخصية | Owner drawings | سحب المالك من الصندوق لاستعماله الخاص — قيد على حساب المسحوبات لا مصروف |

## 8. الذمم والمصالحة

| المصطلح المعتمد | الإنجليزية | المعنى الدقيق في «دِقَّة» |
|---|---|---|
| الذمم المدينة | Receivables | ما على العملاء لنا — مشتقة من الفواتير والمطابقات (`party_balance`) |
| الذمم الدائنة | Payables | ما علينا للموردين |
| المصالحة | Reconciliation | مطابقة كل سداد صراحةً بفواتيره التي يغطيها عبر جدول المطابقات — أساس الذمم كله (07 §1.4) |
| المطابقة | Allocation | صف في `voucher_allocation` يربط جزءاً من السند بفاتورة محددة بمبلغه المطبق |
| السداد الكلي/الجزئي | Full/partial payment | سند يغطي فاتورة كاملة أو جزءاً منها؛ الجزئي طبيعي ولا يحتاج آلية خاصة |
| رصيد مقدّم | Advance balance | سند قبض (أو صرف لمورد) يبقى بلا مطابقة مؤقتاً = رصيد باتجاه معاكس على ذمة الطرف يُطابق لاحقاً يدوياً أو آلياً بالأقدمية — بلا حساب جديد ولا ميزة جديدة (س5) |
| عمر الفاتورة | Invoice age | بجانب كل فاتورة غير مسددة «منذ X يوماً» (من تاريخ الاستحقاق إن وُجد وإلا تاريخ الفاتورة)؛ التقرير التجميعي (30/60/90) مؤكد في م1 بكلمة المالك (2026-10-24 — س5) |
| أعمار الذمم | Aging | تقرير تقسيم الأرصدة بحسب تأخر الفواتير (0–30، 31–60...) مشتق من المطابقات |
| تلقائي بالأقدمية | Auto FIFO allocation | التوزيع الافتراضي للسداد على الفواتير الأقدم أولاً مع إمكانية التعديل اليدوي قبل الترحيل |
| تنبيه حد الائتمان | Credit limit alert | تحذير آلي عندما يتجاوز الرصيد الجاري سقف الائتمان الاختياري المعرف للعميل (F-023) — رسالة من فهرس الرسائل لا منع؛ البائع يرى ويقرر (F-164 — الوجه اللين) |

## 9. الدفتر المحاسبي والقيود

| المصطلح المعتمد | الإنجليزية | المعنى الدقيق في «دِقَّة» |
|---|---|---|
| الدفتر | Ledger | الجانب المحاسبي كله: دليل الحسابات + الدفاتر اليومية + القيود + الفترات |
| دليل الحسابات | Chart of accounts | شجرة الحسابات (وثيقة 03) — بيانات قابلة للتخصيص، لا كود (07 §1.6) |
| الحساب | Account | عقدة في الشجرة بنوع واتجاه طبيعي؛ الحساب الورقي وحده يقيد |
| الحساب الورقي | Leaf account | حساب بلا أبناء تُقيّد عليه الأسطر؛ الحساب الأب يجمع أرصدة أبنائه فقط |
| نوع الحساب | Account type | أحد خمسة: أصول/خصوم/حقوق ملكية/إيرادات/مصروفات — منه تُبنى كل التقارير |
| الاتجاه الطبيعي | Normal side | الجانب الذي يزيد الرصيد: مدين للأصول والمصروفات، دائن للخصوم والإيرادات وحقوق الملكية (مع حسابات عكسية استثنائية مثل مردودات المبيعات) |
| الدفتر اليومي | Journal | دفتر إصدار القيود: مبيعات/مشتريات/صناديق/مخزون/عام (`journal`) |
| القيد | Journal entry (move) | قيد مزدوج مرتبط بفترة ودفتر ومستند مصدر غالباً (`move`) |
| سطر القيد | Entry line | سطر مدين أو دائن على حساب ورقي (`move_line`)؛ قد يحمل طرفاً أو مرجع حركة مخزون |
| التوازن | Balance equality | مجموع المدين = مجموع الدائن في كل قيد — مفروض مرتين: بالمحرك وبقاعدة البيانات (07 §2.2) |
| القيد العكسي | Reversing entry | قيد يعكس قيداً سابقاً بالمرجعية — أدوات التصحيح لا الحذف |
| القيد الافتتاحي | Opening entry | قيد متوازن واحد يُدخل به أرصدة البداية عند التفعيل الأول، يُغلق فرقه على «جاري النتيجة» |
| ميزان المراجعة | Trial balance | تقرير أرصدة الحسابات الورقية مدين/دائن عند تاريخ — يجب أن يتوازن دائماً |

## 14. المزامنة وسجل الأحداث والبنية

| المزامنة التزايدية | Incremental sync | نقل الأحداث الجديدة فقط عند توفّر الشبكة (الأسلوب الثاني D-022) — العمل المحلي لا يتوقف أبداً |

| واجهة المزامنة | SyncAdapter | العقد البرمجي المجرد الذي يجعل تبديل المزوّد إعدادات لا إعادة بناء (D-010) |
| حل التعارض | Conflict resolution | قواعد موثقة لحالتي جهازين عملا منفصلين ثم اتصالا — مبنية على ترتيب الأحداث لا الدمج الأعمى |
| حزمة المجال النقي | Pure domain package | كل منطق الأعمال في Dart بلا Flutter ولا قاعدة بيانات — الواجهة تعرض والتخزين يحفظ (07 §1.8) |
